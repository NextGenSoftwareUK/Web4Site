COMING NEXT · STAGE 3

Write CQL and run it live on SQLite (relational), MongoDB (document) and Neo4j (graph), side by side, with presets from the COSMIC CQL demo: filters, ordering, paging, projections, aggregates, child loading and federation across all three.

1 · Save once, stored everywhere

Save a holon with auto-replication on. WEB4 writes it to every provider in the replication list, then reads it back from each one separately.

2 · Take a provider offline

Pick a provider and take it down for 60 seconds, for your requests only: nobody else using WEB4 is affected, and it always comes back on its own. Then load your holon normally and watch HyperDrive fail over.

3 · Load it and watch failover

The load starts at the provider you picked in step 2. If it is offline, HyperDrive moves down your failover list and serves a replica.

1 · Data from an app that has never heard of OASIS

The sandbox has a separate MongoDB database belonging to a pretend online shop: customers, products and orders, each keyed its own way. Create (or reset) it, then turn it into OASIS holons.

2 · Pick a source and preview the mapping

No mapping is needed: OASIS names each holon from its name/title field, takes the description from summary/description, and keeps every other field as metadata. Override only what you want.

3 · Import it, then import it again

Each holon's id comes from where the record lives, so a second import updates the same holons instead of creating duplicates. Imported holons are ordinary OASIS data: they replicate to every provider.

One object model, any database

COSMIC ORM works with holons: objects with children, metadata and identity that HyperDrive stores on any provider. Each step shows the C# SDK call and the equivalent WEB4 HTTP request. Run sends the HTTP request live, as your demo avatar, and shows the real response.
